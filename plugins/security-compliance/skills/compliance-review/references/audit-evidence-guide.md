# Audit Evidence Guide

Use this guide to identify evidence that supports security and compliance claims.

## Common Evidence Types

- Access review records
- Policy documents and approval history
- Ticket or change records
- CI/CD logs and deployment approvals
- Monitoring, alert, and incident records
- Screenshots, exports, and configuration snapshots

## Evidence Quality Checks

- Is the evidence current for the review period?
- Does it show who performed the action and when?
- Can the evidence be reproduced or traced back to a source system?
- Does it support the exact control being claimed?

## Common Weaknesses

- Policies exist but are not reflected in operations
- Controls are implemented but lack traceable evidence
- Evidence is collected manually and inconsistently
- Ownership is unclear across engineering, security, and compliance teams

## Practical Collection Advice

- Prefer source-system evidence over manually rewritten summaries
- Record ownership for each control and evidence source
- Reuse recurring evidence patterns instead of rebuilding each audit cycle
- Flag areas where automation would improve consistency and review speed
