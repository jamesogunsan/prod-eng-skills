# Dashboard Review Checklist

## Triage First

- Show current service health near the top
- Include latency, error rate, throughput, and saturation before detailed panels
- Make the main dependency and change signals easy to find

## Panel Quality

- Use correct units, percentiles, and time windows
- Avoid overloaded dashboards with too many similar charts
- Prefer panels that answer an operator question directly
- Ensure thresholds and colours reflect operational meaning

## Navigation and Ownership

- Add variables only when they speed up investigation
- Link to runbooks, logs, traces, or deeper dashboards where useful
- Make the owning team or service obvious
- Review stale dashboards and unused panels regularly
